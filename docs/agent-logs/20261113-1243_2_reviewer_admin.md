## Findings (เรียงตามความรุนแรง)
ไม่พบ Critical/High ที่เป็น auth bypass ได้จริงใน deployment ปัจจุบัน

1. **Medium (confirmed)** — admin edit ไม่คงทน: `digest.ts:180-240` `saveEventContent` เขียน `title_th`/`summary_th`/… ทับ event ที่ `published` เมื่อมีบทความใหม่ (`linkedAfterSummary`) และ draft/pending (`llm_failed`) โดยไม่ดูว่า admin เพิ่งแก้; และ `admin/events/[id]/+page.server.ts:69-87` คำนวณ patch จากฟอร์มเก่าเทียบกับแถวปัจจุบัน จึง revert ข้อความที่ digest เพิ่งเขียน (lost update) — ขัด PRD FR-06/§9.2 (แก้ไขข้อผิดพลาดแล้วต้องอยู่)
2. **Medium (confirmed mechanism, ไม่ active ตอนนี้)** — dev bypass compile-out ขึ้นกับ env ตอน build: Vite (`node.js:37706-37711`) ให้ `DEV=true` ถ้า `NODE_ENV` ≠ `production` ตอน `vite build` รวมถึง `NODE_ENV=development` ใน `.env`; ส่วน runtime key `config.nodeEnv === 'development'` เป็นค่า **default** เมื่อไม่ตั้ง `NODE_ENV` (`config.ts:522`) และ adapter-node ไม่ตั้งให้ → ถ้า build ผิด env + runtime ไม่ตั้ง NODE_ENV + ไม่มี `CF_ACCESS_AUD` = admin เปิดไม่ต้องมี token (`admin-guard.ts:277-281`, `hooks.server.ts:23`)
3. **Low (confirmed)** — `cloudflare-access.ts:174` `trim().toLowerCase()` บน Unicode: `\u212Aate@…` → `kate@…` ผ่าน allowlist (probe ยืนยัน); ต้องมี token ที่ CF เซ็นด้วย email นั้น
4. **Low (latent)** — `hooks.server.ts:28` gate อิง raw `event.url.pathname` ไม่ใช่ `event.route.id`; ถ้าเพิ่ม `reroute` หรือ `paths.base` ในอนาคต จะ bypass ได้
5. **Low (spec gap)** — relations: approve/reject จาก `pending_review` เท่านั้น (`admin.ts:231`), ไม่มีทาง unpublish relation ที่ published แล้วผิด (PRD FR-06); pending relation ที่ event ไม่มี category ไม่โผล่ในคิว (`admin.ts:349-350`)
6. **Low** — `rerunIngest` ไม่มี `change_reason`/actor ใน DB (มีแค่ `console.info`), ไม่มี cooldown หลังรันจบ (force), และผลที่ไม่ใช่ claim-skip ถูกรายงานเป็น "กำลังทำงานอยู่" (`manual-ingest.server.ts:54-55`)
7. **Low** — `handleError` log `DrizzleQueryError` ซึ่ง message มี SQL + `params:` (ตัดที่ 200 ตัวอักษร) — log ฝั่ง server เท่านั้น ไม่รั่วไป client
8. **Simplicity** — `cachedVerifier` keyed ด้วย `JSON.stringify(settings)` ทุก request ทั้งที่ config cache ทั้ง process; สร้าง verifier ครั้งเดียวแบบ lazy ก็พอ
